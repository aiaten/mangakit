                                         漫卷 MangaKit 使用文档
====================================================================================================

    | 版本 0.3.0 ｜ 通用漫画批量下载器 ｜ Windows
    | 漫卷 MangaKit 是一个本地规则驱动的漫画下载软件：把漫画网站的页面结构写成 JSON 规则，
    | 由程序直接抓取详情页、章节列表和图片地址并下载。它不走任何第三方服务器，
    | 全部解析在你自己电脑上完成。

一、快速开始
============

1. 直接用 exe（推荐）
---------------------

直接双击 dist\MangaKit.exe 即可，不需要任何 .bat。

当前版本：v0.3.0（dist\MangaKit.exe，174,632,103 字节，2026-10-14 21:31:01 构建）。
exe 已内嵌图标、启动画面与版本资源——右键 → 属性 → 详细信息可以看到
FileVersion = 0.3.0、ProductName = 漫卷 MangaKit。

早期版本必须靠 启动漫卷.bat 才能启动，是因为单文件 exe 要先把自身解压到
%TEMP%\_MEIxxxxxx，一旦 %TEMP% 有问题（条目过多、被清理软件锁住、磁盘满、
被安全软件拦截）就会弹「Could not create temporary directory!」然后秒退。
v0.2.0 已把这套启动器逻辑并进 exe 内部：

  · 固定解包目录：mangakit.spec 里写死了
 runtime_tmpdir=r'%LOCALAPPDATA%\MangaKit\run'，解包落在
 %LOCALAPPDATA%\MangaKit\run\_MEIxxxxxx，不再受 %TEMP% 异常影响。
  · 启动自检在 exe 内：mangakit/main.py 的 _startup_preflight 会在拉起界面前
 检查下载目录能否真正写入，不可写时弹中文 GUI 提示告诉你哪个目录、什么原因，
 而不是丢一句英文报错就退。

启动漫卷.bat 仍然保留在仓库里，定位是「兼容旧习惯的兜底入口 + 参数转发」——
可选用，不用也没关系。exe 单独拷到别的机器时，只拷 exe 一个文件就能跑。

    | ⚠️ 别把 exe 放在开发工具、沙箱、隔离环境的目录里跑。
    | 这类环境普遍限制程序往工作区以外的路径写文件，症状是下载时报
    | 「拒绝访问 / Permission denied」——建目录常常还能成功，但建文件一定失败。
    | 把 exe 放到桌面或「文档」目录即可解决。详见下载报「拒绝访问」。

程序会在首次运行时自动创建数据目录：

3. 命令行模式
-------------

  ┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄
    python -m mangakit --sites                          # 列出所有内置站点
    python -m mangakit --url https://manhuagui.cc/comic/douluodalu     # 解析某个漫画页并列出章节
    python -m mangakit --url <网址> --get 1 --limit 20   # 解析后下载第 1 章的前 20 张
    python -m mangakit --selftest report.txt            # 离线自检（配置/规则/数据库/打包器），结果写文件
  ┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄

参数说明：

  参数             含义
  ---------------------------------------------------------------------------------------
  --url URL        漫画详情页网址，自动识别站点并解析
  --get N          下载第 N 章（不填只解析不下载）
  --limit N        每章最多下载 N 张，默认 8

  --selftest FILE  离线自检，把结果写入 FILE。打包后的 exe 没有控制台，用它来做自动化冒烟

    | 这两个参数请用源码方式运行；要验证 exe 本身是否正常，用 --selftest。

二、图形界面使用
================

界面左侧是七个页面，依次点击即可：

  序号  页面         作用
  ----------------------------------------------------------------
  1     搜索 / 打开  站内搜索或直接粘贴网址
  2     漫画详情     看章节列表、勾选下载、「展开全部章节」
  3     下载任务     进度、暂停/继续/重试、实时日志
  4     收藏         书签、检查更新
  5     设置         下载目录、并发、打包、站点管理
  6     图源仓库     从 yck2026 拉异次元图源，转成规则并验证后导入
  7     内置浏览器   内置 QtWebEngine 浏览器，可直接逛图源站

    | 第 6、7 两页是 v0.2.0 新增的。「内置浏览器」是懒加载的：主窗口启动时
    | 不会创建它，所以你平时根本感觉不到它的存在；只有第一次点开这一页才需要
    | 等待约 3–4 秒（要解包上百 MB 的 Chromium 运行库），之后复用同一个视图，
    | 再切回来就是瞬开。详见下文各节。

1. 搜索 / 打开
--------------

  · 搜索：输入漫画名 → 在下拉框选择站点（默认「全部站点」）→ 回车或点「搜索」。
 「全部站点」会同时向所有启用了搜索的站点并发搜索，哪个站先出结果就先显示哪一批，
 不用等最慢的站（状态栏会显示「已到 N 个结果」，全部结束后变成「完成，共 N 个结果」）。
 不支持搜索的站会自动跳过，状态栏会注明跳过了几个。
  · 封面是异步加载的：结果先以标题占位秒出，封面在后台线程池（6 线程）并行下载，
 取到一张就补一张，下载过程中界面不会卡住。封面缓存在 %TEMP%\mangakit_cover，
 上限 600 张，超出按最旧的删。
 未取到封面时显示的是满尺寸灰色占位图（不是空图标）——占位图保证每格的
 可点击区域从一开始就是整格大小，封面没到也能直接双击打开。
  · 打开结果：双击任意一条结果即可打开该漫画的详情页。
  · 直接打开：点「打开网址…」，粘贴漫画详情页网址即可，走的是与双击结果
 完全相同的链路（同样会切到详情页并解析章节）。
 站点下拉里只列出能站内搜索的站点；其余站点（搜索接口是 JS 异步渲染或已失效）
 已默认隐藏，但仍然能通过「打开网址…」直接用，规则没删。
 下拉里少数能用、但覆盖不全的站会标「（不支持搜索）」，选中按搜索会直接弹窗提示，
 不会白等。

2. 漫画详情
-----------

打开后显示封面、标题、作者、状态、标签，下面是章节列表。

  · 点「重新读取」重新抓一次（站点更新章节后用）。
  · 章节可批量勾选：

  按钮        作用
  ------------------------------
  全选        勾选全部章节
  反选        翻转现有勾选状态
  取消选择    清空勾选
  仅选未下载  只勾还没下过的章节
  选最新20话  快速追新

 章节列表最左边那一列就是勾选框，点方框或点空白处都能勾上；
 点列表上方的表头方框 = 一键全选 / 取消全选。
 点「章节」列的文字只会高亮整行，不会改变勾选状态。
  · 右上角「正序 / 倒序」切换列表顺序，部分站的章节顺序是反的。
  · 勾好后点「下载选中章节」，程序会跳到任务页开始下载。
  · 工具栏还有一个 「在浏览器中打开」 按钮（v0.2.0 新增）：把当前这本漫画的详情页
 网址丢进内置浏览器打开。遇到「详情页解析不出来但网页本身能看」的情况时很有用
 ——先在内置浏览器里确认页面到底长什么样，再决定要不要改规则。

「展开全部章节」按钮
--------------------

不少站点的详情页只渲染最近 20～24 话，剩下的藏在「加载更多章节」按钮后面，
页面 HTML 里根本没有。遇到这种站，工具栏里的 「展开全部章节」 按钮会亮起：

  · 点它 → 程序重新抓一次详情页，这次会走「补齐折叠章节」的两条通道：
    1. chapters.api：站方有章节列表接口（如顶漫画 / D漫画 POST /comic/<id>），
 从接口一次性拿回全部章节（实测顶漫画《利用商人技能以攻略魔王城》24 话 → 677 话，
 D漫画《末日》24 话 → 70 话）；
    2. chapters.embed：完整章节数组直接内嵌在页面脚本里（如神奇漫画的 Next.js
 flight 数据，《秘密教学》20 话 → 333 话），程序从页面里解出来。
  · 展开完状态栏会给出回执：「展开完成：新增 N 话，共 M 话」。
  · 展开前勾好的章节不会丢：勾选状态按章节网址保留，补齐后自动勾回原处；
 展开过程中换了正序/倒序也一样保留。
  · 按钮在展开过程中显示「展开中…」并置灰，展开完自动恢复。
  · 展开只影响章节列表，不影响已下载的文件。

    | 按钮置灰 = 这个站不需要展开。 程序按站点规则里的 chapters.api /
    | chapters.embed 判断该站有没有折叠章节可补。目前 22 个站里只有
    | 顶漫画、D漫画、神奇漫画 三站配了补齐通道。其余站点的详情页 HTML 里
    | 已经给出了全部章节（页面上那个「加载更多 / 查看全部章节」多数只是
    | CSS 展开或 App 引流广告，章节本来就在页面里），所以按钮会置灰并提示
    | 「该站详情页已给出全部章节（或其规则未配置章节接口），无需展开」——
    | 这不是坏了，是真的没有更多可展开。
    | 要加一个新站怎么办：如果某站真的折叠了章节，但按钮是灰的，
    | 说明规则里没配补齐通道。按第七节的方法给它补一条 chapters.api 或
    | chapters.embed 即可，按钮会自动亮起。

3. 下载任务
-----------

  按钮                       作用
  -------------------------------------------------
  全部继续 / 全部暂停        批量控制
  清理已完成                 删除已完成的记录
  暂停 / 继续 / 重试 / 删除  只作用于表格里选中的行
  打开下载目录               直接打开下载文件夹

表格列：漫画、章节、进度、状态、速度（页/秒）、错误信息。
下方是实时日志，每条请求/错误都会打出来。

断点续传：任务进度存在数据库里，软件被强杀、关机、重启后重新打开，
未完成的章节会从已下载的页继续，不会重头再来。

4. 收藏
-------

打开过的漫画会自动进收藏（表格列：漫画、作者、来源、最新章节、上次章节数、状态、上次检查、网址）。

  · 上方输入框可按标题过滤，右下角显示「共 N 条」（过滤时显示「筛出 X / 共 N 条」）。
  · 双击任意一行跳回该漫画详情页，选中后点「打开」同样效果。
  · 删除收藏（三种入口，效果一样）：

  操作                                    说明
  ------------------------------------------------------------
  「删除选中」按钮                        删除选中的行
  右键菜单 → 删除选中                     会显示当前选中了几条
  右键菜单 → 清空收藏 / 「清空收藏」按钮  删除全部收藏

 表格支持 Ctrl / Shift 多选，可以一次删掉好几条。
 删除前一律弹确认框（单条会带上漫画名），清空会额外提示「此操作不可撤销」。
  · 没有收藏时，「删除选中 / 打开 / 清空收藏」会自动置灰。

    | 收藏存在 mangakit.db 的 favorites 表，删除是真的从库里删掉，无法撤销；
    | 已经下载到本地的图片不受影响（收藏只是个书签）。

检查更新
--------

点「检查更新」会去每个源站看收藏的漫画有没有新章节。
选中若干行时只检查选中的，没选中就检查全部收藏。

  · 第一次检查只记录当前进度，不算「有更新」（状态显示绿色的「已记录当前进度」）。
 有了基准之后，再点才会对比出「有 N 话更新」（橙色）。
  · 检查中底部会实时显示「正在检查 3/12 本…」，按钮变「检查中…」并置灰；
 全部查完显示「检查完 N 本，M 本有更新」（有失败会补一句「K 本失败」）。
  · 状态列的含义：

  状态            颜色  含义
  -----------------------------------------------------------
  有 N 话更新     橙色  比上次记录多了 N 话
  已记录当前进度  绿色  首次检查，只是把当前进度存作基准
  无更新          灰    和基准一致
  检查失败        红色  网络/风控等原因没查成，鼠标悬停看原因
  不支持检查      灰    站点已被停用或从规则里删掉了

「最新章节」按话号取，不按列表位置
----------------------------------

有些站的章节列表是倒序的（最新章节在最上面，或旧章节排后面），
按「列表最后一条」取会把第 1 话当成最新章节 —— 这也是「检查完变成第一章」的原因。
现在改成：

  · 按话号取最大：从章节标题里认 `第123话 / 第 123 話 / 第12回 / Chapter 12 /
 123话 / 第12章 / 第3卷` 这些写法，取号最大的那一话。
  · 认不出话号就退回按列表顺序：如果一本漫画里过半的章节标题都认不出话号
 （比如标题全是「序章」「番外」「2026新年贺图」这种），说明这个站的话号不可靠，
 就退回原来的「按解析顺序取最后一条」，不会因为认错而乱报。
  · 更新与否按「章节数」比，同时用话号做补强：真站的话号常有跳号和重复
 （实测某站 1068 话里话号只到 1162），所以主判据是总数差，
 只有当「比旧基准话号更大的章节数」更多时才用它。

「上次章节数」列
----------------

这一列是上一次检查时源站共多少话，专门用来和「现状」对照着看有没有更新。

  · 显示 — 表示还没有基准（没检查过，或刚点过「从现在开始」重置）。
  · 点了「检查更新」之后，这一列仍然显示旧值（不是本次结果），
 鼠标悬停才显示对比：「上次检查时源站共 1060 话／本次 1068 话（多 8 话）」；
 有变化时数字标橙色。
  · 「本次共多少话」在状态列的悬停提示里。
  · 这样设计是因为：如果检查完就把这一列刷成本次值，「上次」和「本次」会立刻相等，
 这一列就没有对照意义了。所以每次检查会把写之前的旧值挪进基准列
 （favorites.base_total），界面上读的是它。

  · 并发 6 路同时查（单本就是一个详情页请求）。实测 8 本：串行 3.0 秒 →
 6 路并发 0.38 秒。
  · 单本最多等 45 秒，超时就记一笔「检查超时」继续下一本，不会让某一本卡死整次检查。
  · 查询失败的不会覆盖基准（否则下次会把旧章节误报成更新）；只检查成功的才更新基准。

5. 设置
-------

  · 下载文件夹：默认 文档\Downloads\MangaKit（即用户目录下）。
  · 并发数：单个章节内同时下几张图，默认 6。网速一般可以调到 4，太快容易被站方限流。
  · 同时下载章节数：默认 3。
  · 重试次数 / 超时：默认 3 次 / 20 秒。
  · 同域限速：同一个域名两次请求的最小间隔（秒），0 = 不限。抓取量大时建议设 0.5～1。
  · 单图体积上限：默认 40 MB，超过判定为异常内容并跳过。
  · 下载后自动打包：不打包 / CBZ / ZIP / PDF / EPUB。
  · WebP 转 PNG：部分阅读器不支持 WebP，建议保持开启。
  · 校验图片有效性：下载后验证文件头，跳过伪装成图片的广告页。
  · 超长图自动切割：某些站的单页是几千像素的长条图，超过阈值会切成多段，方便阅读。
  · Referer 策略：很多图床会校验来源页，默认「章节页（最稳）」；被拒 403 时可试试「站点首页」。
  · 站点管理：表格里可以逐个启用/禁用站点。某个站出问题时先禁用它，不影响其他站。
 表格下方还有两个按钮：
    · 添加网站：贴入一个漫画详情页网址，程序自动探测这个站能不能下载，
 能下才让你加（详见下面「三、支持的站点 → 自己添加网站」）。
    · 删除站点：删掉自己添加的站点。内置站点删不掉（只能取消左边的勾来停用），
 选中内置站点点它会有一句提示。

改完点「保存」生效；点「恢复默认」还原所有配置。

自己添加网站（不用写规则文件）
------------------------------

这是给「我常看的站不在内置列表里」准备的。不需要会写代码，也不需要手改 JSON：

  1. 在浏览器里打开那个站的某本漫画的详情页（就是能看到章节列表的那一页），
 把地址栏的网址复制下来。注意要贴详情页，不是网站首页 —— 首页上找不到章节。
  2. 打开漫卷 → 设置 → 站点管理 → 点「添加网站」。
  3. 把网址粘进去，点「开始探测」。程序会自己：打开这个页面 → 找出章节链接 →
 抓一话看看能不能拿到正文图片 → 真下几张图试试 → 顺带找找这个站的搜索入口。
 通常几秒，慢的站要几十秒。
  4. 看结果：
     · 显示「探测通过：这个站可以下载 ✅」，下面的「添加到站点列表」按钮会亮起来。
 点它，这个站就加进来了，名字前面带 [自建]。
     · 显示「探测未通过 ❌」，按钮是灰的，加不了。下方会写清楚为什么。

为什么会有站探测不过？ 因为不是所有站都能靠「读懂网页」来下载：

  探测不过的原因          说明                                                                能不能救
  ----------------------------------------------------------------------------------------------------------------------
  图片靠 JavaScript 现拼  网页源码里根本没有图片地址，是浏览器打开后临时算出来的（            需要写专门适配器，暂时不行
                          常带服务端签名）。典型：动漫屋 dm5。
  拿不到正文图片          页面能打开，但图片要么要登录、要么被付费墙挡住                      换个不需要登录的站试试
  找不到章节链接          贴的是首页/列表页，或者是完全靠 JS 填章节的站                       确认贴的是详情页
  页面打不开              域名解析失败、站点关停、或者你本地网络到不了                        先在浏览器里确认能打开
  生成的规则跑不通        少数站结构太特殊，自动生成的规则在引擎里解析不出东西                需要手写规则文件

程序宁可拒绝添加，也不会给你加一个下下来全是广告图的死站。这是刻意的：
内置的每条规则都经过实测，自建的也应该有这个起码的保证。

想删掉自己加的站：在站点管理表格里选中它，点「删除站点」，确认一下就行。

6. 图源仓库（v0.2.0 新增）
--------------------------

左侧导航第 6 项。这是从图源社区批量导入规则的入口，不用你手工写 JSON。

数据来源是 yck2026 图源仓库（<https://www.yck2026.fun/yiciyuan/tuyuan/index.html>）：
把里面的异次元格式图源拉下来 → 转成 MangaKit 的规则 → 后台自动跑
四关探测 + 规则引擎回跑校验 → 只有验证通过才会加进站点列表。

页面提供：

  · 顶部工具条：关键词输入框（留空 = 看全部，输入站名/标题后回车即搜）、
 排序下拉（按更新时间 / 按下载量）、刷新按钮。列表走后台线程，界面不会卡。
  · 图源表格，六列：名称 / 网址 / 更新时间 / 分享者 / 下载量 / 支持搜索。
 表格是只读的，一次选一行（单击整行即可）。
  · 「验证并添加」：对选中的那一条走完整链路 —— 后台校验（会真的下一张图，
 所以可能要十几秒）→ 通过后写入自定义站点规则。成功时状态栏会报
 「可转换：N 话 / M 张图」，并立刻出现在「设置 → 站点管理」里，和手工添加的
 规则完全一样、可以手动删掉。
  · 「在浏览器中打开」：把这个图源站的页面丢进内置浏览器（见第 7 节）看实际效果。
  · 只有校验通过（ok=True）才会写库：不通过就只报原因、绝不落盘一条死规则。
  · 失败条目会直接写出中文原因，不是沉默失败。

会失败的图源：这是设计，不是 bug
--------------------------------

本项目不实现解密。 异次元 App 的图源里有一部分关键字段是被 App 内部加密/编码的，
MangaKit 只支持明文图源，遇到加密串会明确拒绝而不是假装成功。

实测口径（抽样 60 条源）：

  分类                    条数  说明
  ----------------------------------------------------------------------------------------------
  整段字段是不透明加密串  32    例如 :_R002_ 这类字符串，要 App 内部算法才能还原，客户端无法解密
  含脚本（@js: 等）       14    规则里带 JS 代码，MangaKit 的规则引擎不执行图源脚本
  明文可转                14    可正常转换并进入验证流程

也就是说 60 条里 46 条不可转，只有 14 条是明文可转的。

失败时你会看到类似这样的中文提示：

  ┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄
    加密源：关键字段被 App 内部解密，客户端不支持
  ┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄

看到「加密源」三个字就说明是上面第一类，换一条源即可——这不是程序坏了。

7. 内置浏览器（v0.2.0 新增）
----------------------------

左侧导航第 7 项。基于 QtWebEngine 内核的真浏览器，默认打开
yck2026 图源索引页，用来肉眼确认图源站到底能不能打开、页面结构是否还正常。

  · 工具栏：地址栏 / 前进 / 后退 / 刷新 / 回首页。
  · 详情页与图源仓库页都有「在浏览器中打开」按钮，会把对应网址直接丢进来。
  · 懒加载：主窗口启动时不加载它，所以启动速度和以前一样。
 第一次点进这一页要等约 3–4 秒（要解包上百 MB 的 Chromium 运行库），
 之后复用同一个视图，来回切换都是瞬开。
 第一次进入时那几秒的白屏/无响应是正常的解包过程，不是卡死。

    | 体积代价：加上内置浏览器后，exe 从 63 MB 涨到 174.6 MB。
    | 这是嵌入 Chromium 客户端的硬代价，无法通过配置关掉；
    | 如果你完全不需要这一页，只能用不带浏览器的旧版本。

  ZIP   普通压缩包
  PDF   img2pdf 生成，适合打印
  EPUB  电子书格式，元数据从漫画标题写入

    # 下第 5 章前 30 张（先试水别一次拉太多）

  ┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄

批量下载建议写个小脚本：先用 --url 拿到章节列表，再对每章调一次 --get。

六、自行添加新站点
==================

漫画站改版很频繁，软件把「怎么解析一个站」完全交给 JSON 规则，
你可以自己加新站，不用改代码。

步骤
----

    | 先试设置 → 站点管理 → 「添加网站」：多数站能自动搞定，不用往下看。
    | 只有在自动探测被拒（图靠 JS 现拼、要登录等）时，才需要手写规则。

  1. 找到漫画详情页 URL，看它的域名是不是新的。
  2. 复制模板：复制 mangakit/rules/templatedm.json 为 mangakit/rules/你的站点id.json。
  3. 用浏览器开发者工具（F12）看三处：详情页、章节列表、章节页的图片，
 把对应的 CSS 选择器填进规则。
  4. 命令行验证：python -m mangakit --url <你的详情页> --get 1 --limit 3。
  5. 确认能下载后，在设置里勾选启用。

手写的规则文件放在 mangakit/rules/ 下；如果想让规则跟着配置文件走（不依赖程序目录），
可以改用「添加网站」加进去 —— 两种方式在引擎眼里是等价的。

字段选项
--------

  写法                        含义
  ----------------------------------------------------------------------------------------------------------------------
  "css": "..."                CSS 选择器；装了 cssselect 后支持 a[href*='/chapter/'] 这类写法
  "attr": "..."               取 HTML 属性（src / data-original / href / content / 任意自定义属性）
  "text": true                取元素文本
  "text": "direct"            只取元素自己的文字，不含内部子元素。标题里塞了分类标签时必须用它，否则标题会变成「作品名
                              都市 恋爱」
  "all": true                 取所有匹配元素的文本，而不是第一个
  "attr": ["content", "src"]  依次试多个属性，取第一个非空的（桌面/手机两套模板并存时用）
  "re": "作者：(.+)"          对取到的文本再套一层正则，用第 1 个捕获组
  "url": false                关掉自动补全网址。默认值会把取到的值当相对地址拼到当前页上；取 title / aria-label
                              这类纯文本属性时必须写它，否则「海贼王」会变成 https://站点/海贼王

常见情况怎么处理
----------------

  页面情况                                           做法
  ----------------------------------------------------------------------------------------------------------------------
  图片在 data-src / data-original 等懒加载属性       "url": {"attr": "data-original"}
  图片列表在 JS 变量里                               用 lazy_js 正则抓，多个值用 split 指定的分隔符隔开
  图片列表在 JSON 里                                 lazy_js 抓整个 JSON 数组（正则带括号），程序会自动解析
  页面只给「图片前缀 + 总张数」，不列 URL            把 lazy_js 写成字典（见下）
  标题元素里套着分类标签                             标题选择器加 "text": "direct"
  图片 URL 里有重复路径段 / 要换域名                 用 pages.replace 做正则替换
  章节页混着封面和广告图                             用 pages.filter 白名单正则过滤
  章节链接里混着别的链接                             用 chapters.url_re 过滤
  章节链接要改成另一种形式（如多页版 → 单页滚动版）  用 chapters.url_replace 正则改写，改写后撞车的会被去重
  详情页只渲染最近 20 话，其余在「加载更多」后面     加 chapters.api（有接口）或 chapters.embed（数据内嵌在页面里），
                                                     见下
  取的是 title/aria-label 这种文本属性               规格里加 "url": false，否则会被拼成假网址
  站需要登录                                         在规则里填 cookies，或用 --selftest 之外的方式手动带
  站搜索接口 500 / 是 JS 异步渲染                    删掉 search 段（GUI 会提示「不支持搜索」，改用「打开网址…」）
  页面是 gb2312/GBK 编码                             程序已自动处理，不用管

    | 注意：verify.py 现在会对声明了搜索关键词的用例断言搜索结果非空，
    | 所以规则写完后搜索坏掉不会再「全绿蒙混过关」。

lazy_js 写成字典：按张数展开图片
--------------------------------

有些站不逐张列出图片 URL，只在 JS 里给一个前缀和一个总张数：

  ┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄
    "pages": {
      "lazy_js": {
        "prefix": "var\\s+pasd\\s*=\\s*[\"']([^\"']+)[\"']",     // 第 1 个捕获组 = 图片前缀
        "count":  "var\\s+num\\s*=\\s*eval\\(\\s*[\"']?(\\d+)", // 第 1 个捕获组 = 总张数
        "start":  1,        // 从第几张开始（可写在 lazy_js 里或 pages 层）
        "suffix": ".webp",  // 每张的后缀（同上）
        "width":  3         // 序号补零宽度，如 001（同上）
      },
      "filter": "\\.webp$"
    }
  ┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄

展开结果就是 前缀 + 1 + .webp、前缀 + 2 + .webp …… 直到张数用完。

replace：修正图片 URL
---------------------

  ┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄
    "replace": "/kblmh//kblmh/"        // 单个正则 → 删掉匹配到的部分
    "replace": [["/old/", "/new/"]]    // 或 [[正则, 替换], ...] 逐条替换
  ┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄

在 filter 之后、去重之前执行 —— 专门对付图床下发畸形 URL 的情况
（如重复路径段，双层路径 404、去掉一层就 200）。

chapters.api / chapters.embed：补齐折叠章节
-------------------------------------------

很多站的详情页只画最近 20 话，剩下的在「加载更多章节」按钮后面，HTML 里根本没有。
配了这两条之一后，GUI 的「展开全部章节」按钮就能把它们补回来。

通道 1 chapters.api —— 站方有章节列表接口：

  ┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄
    "api": {
      "url": "https://www.dingmanhua.com/comic/{id}",
      "method": "POST",
      "data": {},
      "list": "data.chapters",
      "title": "chapterName",
      "chapter_url": "/chapter/{contentId}-{id}.html",
      "headers": { "X-Requested-With": "XMLHttpRequest" }
    }
  ┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄

  · {id} 是详情页 URL 的最后一段（comic/278.html → 278，会自动去掉 .html 后缀）。
  · list 是结果里的路径，$.* 表示根数组。
  · 章节地址的模板键不能叫 url（那个键已经被接口地址占用了），用 chapter_url；
 模板里可用接口返回的全部字段加 {id}/{cid}/{slug}（去后缀的 id）。
  · 接口报错只会记一条 warning 日志并返回空列表，不会让展开失败。

通道 2 chapters.embed —— 完整数组就内嵌在页面脚本里：

  ┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄
    "embed": {
      "start": "\\\"chapters\\\":(\\[)",
      "item": "\"id\":\"([^\"]+)\",\"title\":\"([^\"]*)\"",
      "fields": ["id", "title"],
      "url": "/read/{comic_id}/{id}"
    }
  ┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄

  · start 在原始 HTML 上匹配，第 1 个捕获组是数组起点；程序从那里做括号配平
 截出完整 JSON 片段，再 json.loads 还原转义（别用 unicode_escape 手工解码，中文会乱）。
  · item 作用在已反转义的文本上，所以只需要匹配普通原文，不用写双层反斜杠。
  · url 模板可用 fields 里的占位符，外加 {comic_id} / {cid}（作品 id）。
  · HTML 里同一个键可能出现多次（如 Next.js 的 "chapters" 有时是 $22:props:... 这种引用），
 start 写得不够精确就可能匹到引用而不是数组 —— 写完务必跑一次 verify.py 看章节数对不对。

    | 两条通道都只在用户点「展开全部章节」时才走，正常打开漫画不受影响，
    | 也不会拖慢首屏。

下载报「拒绝访问 / Permission denied」
--------------------------------------

这是最常见的一类报错，而且大多数情况不是程序坏了，是程序被放在了一个写不进去的地方。

新版在下载前会做一次真实落盘自检（建目录 + 试建文件），失败时直接报：

  ┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄
    无法写入目录：C:\Users\你的用户名\Downloads\MangaKit\某本漫画
    原因：系统拒绝访问（权限不足，或该目录被其它程序占用）
    怎么办：
      1) 把 MangaKit.exe 移到桌面或「文档」目录再运行
      2) 或在「设置 → 下载目录」改一个能写的路径
      3) 关掉占用该目录的其它程序
  ┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄

按顺序排查：

「Could not create temporary directory!」已内建解决
---------------------------------------------------

成因：单文件（onefile）exe 启动时要把自己解压到一个临时目录。v0.2.0 之前的版本默认用
%TEMP%\_MEIxxxxxx，一旦 %TEMP% 不可写（条目过多、被清理软件锁住、磁盘满、
被安全软件拦截），解压失败，PyInstaller 就弹这个英文框然后秒退。

v0.2.0 的处理：

  · mangakit.spec 显式指定 runtime_tmpdir=r'%LOCALAPPDATA%\MangaKit\run'，
 解包固定落在 %LOCALAPPDATA%\MangaKit\run\_MEIxxxxxx，绕开了 %TEMP% 的所有毛病。
  · mangakit/main.py 的 _startup_preflight 在拉起界面前做真实落盘自检，
 下载目录不可写时弹中文 GUI 提示（写清目录、原因、怎么办），不再是一句英文后消失。

所以你该做的：直接双击 MangaKit.exe。如果还是弹这个框，说明连
%LOCALAPPDATA% 都不可写（极少数被组策略锁死的机器），此时才需要临时把
TEMP/TMP 指到一个可写目录，或改用 启动漫卷.bat 这个兜底入口。

内置浏览器第一次打开要等几秒
----------------------------

点左侧第 7 项「内置浏览器」时，第一次有约 3–4 秒的等待，界面可能短暂白屏。
这是因为浏览器内核（QtWebEngine，上百 MB 的 Chromium 运行库）是懒加载的：
主窗口启动时刻意不加载它——否则每个用户每次开软件都要多等好几秒。
首次进入时才解包 + 初始化，之后复用同一个视图，切走再切回是瞬开。

这不是卡死，不需要强杀进程重开。若超过 30 秒仍无反应，才按「软件打不开 / 闪退」
那一条排查（看日志、检查杀软是否拦截了 exe 的解包）。

验证 exe 本身是否正常
---------------------

打包后的 exe 没有控制台，用文件输出的自检通道：

  ┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄
    MangaKit.exe --selftest r.txt
  ┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄

自检项全 OK 会以 SELFTEST PASS 结尾；结果也会写到同目录 selftest.txt。
v0.2.0 的自检新增了 webengine 项（「页面可加载、JS 可执行」），
所以它同时能验证内置浏览器内核在你这台机器上能否正常工作。

重新获取已过期签名（kanman）
----------------------------

kanman 的图片地址带时间戳签名。正确做法：重新打开该章节的详情/阅读页，让程序重新解析一次，
再点下载。不要拿几小时前复制的旧章节列表反复重试。

八、数据与隐私
==============

  · 所有抓取、解析、下载都在本机完成，不经过任何第三方服务器。
  · 只向漫画站点发请求。程序不会上传任何数据。
  · 数据都在 %APPDATA%\mangakit\：配置、数据库、日志（该目录不可写时会自动改用 exe 旁的 MangaKitData\）。
  · 卸载：删掉 exe 和 %APPDATA%\mangakit\ 目录即可，没有注册表项、没有系统服务。
  · 想换数据目录，设环境变量 MANGAKIT_HOME。
  · 请遵守目标站点的版权规定与 robots 协议，仅供个人学习与备份使用。

    |  支持多选与右键菜单，底部实时显示条数，空库时按钮自动置灰。
    | - 「展开全部章节」原本只看章节列表非空就点亮。实测 22 个站里只有 3 个
    |  配了补齐通道，用户在其余站点点下去只会白等一次完整重载、列表纹丝不动，
    |  且没有任何提示，看着就像功能坏了。现在按钮可用性由 Site.can_expand
    |  决定：支持的站点亮起并说明「点此展开折叠隐藏的其余章节」，不支持的置灰并
    |  说明「已给出全部章节，无需展开」；展开完成后再给一句
    |  「展开完成：新增 N 话，共 M 话」的回执。

    |  抛 TypeError: 'int' object is not iterable 把搜索打断；现在先判 int
    |  再走列表分支。

    |  引擎的 Selector+url_re 去认，两者不等价。早期版本出现过「探测报 62 话、
    |  实测图片可下载」，写成规则后引擎解析出 0 章（标题还识别成导航栏的「登录」）。
    |  现在 _verify_rule() 会把生成的规则真跑一遍 parse_chapters/parse_pages，
    |  不过就拒绝添加 —— 宁可拒，也不写一条看着能用的死规则。

    |  原本没有任何状态文字（status_msg 是个写 5 次、读 0 次的裸属性），双击后
    |  页面确实在解析、数据也真的到了，但屏幕上除了列表变空什么提示都没有，
    |  用户就判成「点了完全没反应」。现在详情页多了一行可见状态
    |  （「解析中…」→「已找到漫画，正在读取章节…」→「已载入 N 话」/「没有解析到
    |  任何章节」/「解析失败：原因」），且失败也会写状态栏，不只弹一个框。
    | - 旧 exe 必须重打包这条防的是「修了却测不出来」：用户运行的是 17:35 打的
    |  exe，而源码 18:06 才加上流式搜索，结果用户那边跑的还是老逻辑
    |  （search_done 回的是列表而非总数，且没有 search_partial）。
    |  tools\t_exe_ver.py 专门核对 exe 与源码的修改时间，打包后必跑一次。
    | - 收藏「检查更新」卡住这条防的是「异常被框架吞掉」：FavoritesPage.__init__
    |  原本不收 svc，而 _check_updates() 里写着 self.svc.check_updates(...)，
    |  于是每次点击都在槽函数里抛 `AttributeError: 'FavoritesPage' object has no

    |  入口一致的 _guard 异常守卫。同时修掉了进度文案被 reload() 盖掉的问题：
    |  _check_updates() 先写「正在检查 N 本…」，紧接着调的 reload() 又无条件写回
    |  「共 N 条」，用户盯着一个不动的数字，观感同样是「卡住了」。

    |  CoverLoader.get() 未命中时原来返回空 QPixmap，而结果列表开了
    |  setUniformItemSizes(True) —— Qt 会用「无图标条目」的大小把所有条目的

    |  点得动；没命中缓存的条目就是小矩形，点不动 —— 取决于该封面有没有被缓存过。
    |  现在 get() 一律返回满尺寸的灰色占位图，条目从创建那一刻起就是可点的。

    |  request_id（对比 MangaPage 一直有 _rid_c/_rid_ch）。连续搜两次时，

    |  把新搜索收尾（按钮变回可点、状态显示「完成，共 0 个结果」）。现在三条信号
    |  入口都先比对 self._rid，不是本次搜索的一律丢弃。

    |  MangaPage —— 详情页的 _rid_c 从没被赋值，comic_loaded 到达时被自己的
    |  守卫拦掉，页面也不会切过去，用户输完网址「什么都没发生」。现在改成
    |  emit open_comic，与双击结果走同一条链路。

    |  try/except/finally 包住，无论成功失败，search_done 必发一次；

9.5 「测试把用户收藏清空」事故与数据隔离护栏
--------------------------------------------

这一节记的是 2026-10-14 一次真实数据事故，以及为防止它再发生而加的护栏。
如果你要改 tools\ 下的测试脚本，请先读完这一节。

发生了什么：用户在界面里发现收藏全没了。事后定位到：
tools\gui_smoke.py 的界面检查函数直接调用了 store().clear_favorites()，
而这个脚本没有隔离数据目录 → store() 落到 %APPDATA%\mangakit\mangakit.db，
也就是用户真实的库。测试先清空、再塞 4 条测试数据、最后又清空一次，
用户的真实收藏就这样没了。

为什么静态检查防不住：第一版的护栏检查想靠「扫源码里有没有写接口调用」来
判断危险脚本，结果它放过了 tools\t_fix_check.py —— 那个文件全文没有任何写
接口，却照样往真库写了，因为写操作藏在产品代码里：

  ┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄
    MangaPage._on_comic  →  内部自动 store().add_favorite()
  ┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄

「这个脚本会不会写」在静态层面根本无法判定。所以护栏不能依赖判断。

现在的护栏（两层）：

  1. 单点防护（主要）：mangakit\config.py 的 _dev_sandbox()。
 只要进程是从 <仓库>\tools\xxx.py 启动的，数据目录一律改到临时目录
 %TEMP%\mk_dev_xxxx，绝不碰 %APPDATA%\mangakit。
 判定依据是启动脚本路径（sys.argv[0]），不是当前目录，所以 os.chdir 也不会误判。
  2. 显式声明（辅助）：测试脚本自己在顶部设 MANGAKIT_HOME
 （gui_smoke.py / t_fix_check.py / t_gui_new_pages.py / selfcheck.py 都有），
 必须在任何 import mangakit 之前，否则配置已经按真目录读进来了。

正常使用不受影响（tools\check_dev_guard.py 会逐条验证）：
python -m mangakit、python main.py、打包后的 exe、用户自己设的
MANGAKIT_HOME —— 这四种都照常拿真库。护栏只拦「从 tools\ 下起的脚本」。

逃生门：确需连真库调试，设 MANGAKIT_ALLOW_REAL_HOME=1。

验证方式（两条，都是可执行断言而不只是文档约定）：

  脚本                      验证什么
  --------------------------------------------------------------------------------------------------------------
  tools\check_isolation.py  从 tools\ 起的进程落到临时目录；外部同名 tools\ 不被误伤；逃生门有效
  tools\check_dev_guard.py  反向验证：-m mangakit / main.py / frozen / 显式 MANGAKIT_HOME 四种正常用法都拿到真库

最有力的一条证据：把当年肇事的那套测试（tools\gui_smoke.py，含
「清空收藏生效」这条断言）对真库跑一遍，跑完 mangakit.db 的 SHA256
逐位不变。修复前它会清空收藏，现在它连一个字节都碰不到。

顺带修掉的一处同类隐患：tools\gui_smoke.py 里有一条断言把「自建站点数量」
写死成 自建 1，而用户自己通过图源仓库加过站，实际是 自建 2 →
测试在用户的真实配置上必然失败。已改成先读当前数量再断言。

    | 事故取证（冻结副本、字节级打捞脚本、恢复出的收藏清单）保留在
    | tools\_incident\。该目录已加进 .gitignore，里面是本机用户的真实数据库副本，> 绝不能被提交或外发。
