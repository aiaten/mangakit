                                         漫卷 MangaKit 使用文档
====================================================================================================

    | 版本 0.1.0 ｜ 通用漫画批量下载器 ｜ Windows
    | 漫卷 MangaKit 是一个本地规则驱动的漫画下载软件：把漫画网站的页面结构写成 JSON 规则，
    | 由程序直接抓取详情页、章节列表和图片地址并下载。它不走任何第三方服务器，
    | 全部解析在你自己电脑上完成。

一、快速开始
============

1. 直接用 exe（推荐）
---------------------

请双击 启动漫卷.bat，不要直接双击 MangaKit.exe。

启动漫卷.bat 是启动器：单文件 exe 运行前要先把自身解压到临时目录
（%TEMP%\_MEIxxxxxx），如果你电脑的 %TEMP% 目录有问题（条目过多、
被清理软件锁住、磁盘满了、被安全软件拦截），解压就会失败，exe 会弹一个
「Could not create temporary directory!」的英文报错框然后秒退。

启动器做的事情很简单：把 TEMP / TMP 指向 exe 旁边一个干净的 .tmp
文件夹，清掉上次残留的 _MEI*，再启动 exe。以后每次都双击这个 .bat
即可。首次启动会在 exe 旁边生成 .tmp\ 文件夹，正常使用时可以不管它
（退出程序后可以整个删掉）。

如果 MangaKit.exe 单独拷到别的机器，请把 启动漫卷.bat 一起拷过去
（放在 exe 同一目录，或 exe 的上级目录）。

    | ⚠️ 别把 exe 放在开发工具、沙箱、隔离环境的目录里跑。
    | 这类环境普遍限制程序往工作区以外的路径写文件，症状是下载时报
    | 「拒绝访问 / Permission denied」——建目录常常还能成功，但建文件一定失败。
    | 把 exe 放到桌面或「文档」目录即可解决。详见下载报「拒绝访问」。
    | 如果直接双击 MangaKit.exe 弹出一个英文报错框
    | 「Could not create temporary directory!」然后秒退 —— 那个和下载无关，
    | 是单文件 exe 解压失败，同样用 启动漫卷.bat 启动就能绕开。

程序会在首次运行时自动创建数据目录：

  ┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄
    C:\Users\<你的用户名>\AppData\Roaming\mangakit\
    ├── config.json      配置（下载目录、并发、打包方式等）
    ├── mangakit.db      任务、章节进度、收藏（SQLite）
    └── logs\
        └── mangakit.log 运行日志（出问题时先看这里）
  ┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄

    | 便携模式：如果 AppData\Roaming 不可写（例如公司电脑的权限限制、杀软拦截），
    | 程序会自动把数据目录改放到 exe 旁边的 MangaKitData\ 文件夹，
    | 整个程序目录拷到 U 盘也能用。想手动指定，设环境变量 MANGAKIT_HOME 即可。

3. 命令行模式
-------------

  ┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄
    python -m mangakit --sites                          # 列出所有内置站点
    python -m mangakit --url https://manhuagui.cc/comic/douluodalu     # 解析某个漫画页并列出章节
    python -m mangakit --url <网址> --get 1 --limit 20   # 解析后下载第 1 章的前 20 张
    python -m mangakit --selftest report.txt            # 离线自检（配置/规则/数据库/打包器），结果写文件
  ┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄

参数说明：

  参数             含义
  ---------------------------------------------------------------------------------------
  --url URL        漫画详情页网址，自动识别站点并解析
  --get N          下载第 N 章（不填只解析不下载）
  --limit N        每章最多下载 N 张，默认 8
  --sites          列出内置站点及启用状态
  --selftest FILE  离线自检，把结果写入 FILE。打包后的 exe 没有控制台，用它来做自动化冒烟
  --version        版本号

    | 打包后的 MangaKit.exe 是 windowed（双击不弹黑框），因此 --url / --sites 的输出看不到。
    | 这两个参数请用源码方式运行；要验证 exe 本身是否正常，用 --selftest。

二、图形界面使用
================

界面左侧是五个页面，依次点击即可。

1. 搜索 / 打开
--------------

  · 搜索：输入漫画名 → 在下拉框选择站点（默认「全部站点」）→ 回车或点「搜索」。
 「全部站点」会同时向所有启用了搜索的站点并发搜索，哪个站先出结果就先显示哪一批，
 不用等最慢的站（状态栏会显示「已到 N 个结果」，全部结束后变成「完成，共 N 个结果」）。
 不支持搜索的站会自动跳过，状态栏会注明跳过了几个。
  · 封面是异步加载的：结果先以标题占位秒出，封面在后台线程池（6 线程）并行下载，
 取到一张就补一张，下载过程中界面不会卡住。封面缓存在 %TEMP%\mangakit_cover，
 上限 600 张，超出按最旧的删。
  · 直接打开：点「打开网址…」，粘贴漫画详情页网址即可。
 站点下拉里只列出能站内搜索的站点；其余站点（搜索接口是 JS 异步渲染或已失效）
 已默认隐藏，但仍然能通过「打开网址…」直接用，规则没删。
 下拉里少数能用、但覆盖不全的站会标「（不支持搜索）」，选中按搜索会直接弹窗提示，
 不会白等。

2. 漫画详情
-----------

打开后显示封面、标题、作者、状态、标签，下面是章节列表。

  · 点「重新读取」重新抓一次（站点更新章节后用）。
  · 章节可批量勾选：

  按钮        作用
  ------------------------------
  全选        勾选全部章节
  反选        翻转现有勾选状态
  取消选择    清空勾选
  仅选未下载  只勾还没下过的章节
  选最新20话  快速追新

 章节列表最左边那一列就是勾选框，点方框或点空白处都能勾上；
 点列表上方的表头方框 = 一键全选 / 取消全选。
 点「章节」列的文字只会高亮整行，不会改变勾选状态。
  · 右上角「正序 / 倒序」切换列表顺序，部分站的章节顺序是反的。
  · 勾好后点「下载选中章节」，程序会跳到任务页开始下载。

「展开全部章节」按钮
--------------------

不少站点的详情页只渲染最近 20～24 话，剩下的藏在「加载更多章节」按钮后面，
页面 HTML 里根本没有。遇到这种站，工具栏里的 「展开全部章节」 按钮会亮起：

  · 点它 → 程序重新抓一次详情页，这次会走「补齐折叠章节」的两条通道：
    1. chapters.api：站方有章节列表接口（如顶漫画 / D漫画 POST /comic/<id>），
 从接口一次性拿回全部章节（实测顶漫画《利用商人技能以攻略魔王城》24 话 → 677 话，
 D漫画《末日》24 话 → 70 话）；
    2. chapters.embed：完整章节数组直接内嵌在页面脚本里（如神奇漫画的 Next.js
 flight 数据，《秘密教学》20 话 → 333 话），程序从页面里解出来。
  · 展开完状态栏会给出回执：「展开完成：新增 N 话，共 M 话」。
  · 展开前勾好的章节不会丢：勾选状态按章节网址保留，补齐后自动勾回原处；
 展开过程中换了正序/倒序也一样保留。
  · 按钮在展开过程中显示「展开中…」并置灰，展开完自动恢复。
  · 展开只影响章节列表，不影响已下载的文件。

    | 按钮置灰 = 这个站不需要展开。 程序按站点规则里的 chapters.api /
    | chapters.embed 判断该站有没有折叠章节可补。目前 22 个站里只有
    | 顶漫画、D漫画、神奇漫画 三站配了补齐通道。其余站点的详情页 HTML 里
    | 已经给出了全部章节（页面上那个「加载更多 / 查看全部章节」多数只是
    | CSS 展开或 App 引流广告，章节本来就在页面里），所以按钮会置灰并提示
    | 「该站详情页已给出全部章节（或其规则未配置章节接口），无需展开」——
    | 这不是坏了，是真的没有更多可展开。
    | 要加一个新站怎么办：如果某站真的折叠了章节，但按钮是灰的，
    | 说明规则里没配补齐通道。按第七节的方法给它补一条 chapters.api 或
    | chapters.embed 即可，按钮会自动亮起。

3. 下载任务
-----------

  按钮                       作用
  -------------------------------------------------
  全部继续 / 全部暂停        批量控制
  清理已完成                 删除已完成的记录
  暂停 / 继续 / 重试 / 删除  只作用于表格里选中的行
  打开下载目录               直接打开下载文件夹

表格列：漫画、章节、进度、状态、速度（页/秒）、错误信息。
下方是实时日志，每条请求/错误都会打出来。

断点续传：任务进度存在数据库里，软件被强杀、关机、重启后重新打开，
未完成的章节会从已下载的页继续，不会重头再来。

4. 收藏
-------

打开过的漫画会自动进收藏（表格列：漫画、作者、来源、网址）。

  · 上方输入框可按标题过滤，右下角显示「共 N 条」（过滤时显示「筛出 X / 共 N 条」）。
  · 双击任意一行跳回该漫画详情页，选中后点「打开」同样效果。
  · 删除收藏（三种入口，效果一样）：

  操作                                    说明
  ------------------------------------------------------------
  「删除选中」按钮                        删除选中的行
  右键菜单 → 删除选中                     会显示当前选中了几条
  右键菜单 → 清空收藏 / 「清空收藏」按钮  删除全部收藏

 表格支持 Ctrl / Shift 多选，可以一次删掉好几条。
 删除前一律弹确认框（单条会带上漫画名），清空会额外提示「此操作不可撤销」。
  · 没有收藏时，「删除选中 / 打开 / 清空收藏」会自动置灰。

    | 收藏存在 mangakit.db 的 favorites 表，删除是真的从库里删掉，无法撤销；
    | 已经下载到本地的图片不受影响（收藏只是个书签）。

5. 设置
-------

  · 下载文件夹：默认 文档\Downloads\MangaKit（即用户目录下）。
  · 并发数：单个章节内同时下几张图，默认 6。网速一般可以调到 4，太快容易被站方限流。
  · 同时下载章节数：默认 3。
  · 重试次数 / 超时：默认 3 次 / 20 秒。
  · 同域限速：同一个域名两次请求的最小间隔（秒），0 = 不限。抓取量大时建议设 0.5～1。
  · 单图体积上限：默认 40 MB，超过判定为异常内容并跳过。
  · 下载后自动打包：不打包 / CBZ / ZIP / PDF / EPUB。
  · WebP 转 PNG：部分阅读器不支持 WebP，建议保持开启。
  · 校验图片有效性：下载后验证文件头，跳过伪装成图片的广告页。
  · 超长图自动切割：某些站的单页是几千像素的长条图，超过阈值会切成多段，方便阅读。
  · Referer 策略：很多图床会校验来源页，默认「章节页（最稳）」；被拒 403 时可试试「站点首页」。
  · 站点管理：表格里可以逐个启用/禁用站点。某个站出问题时先禁用它，不影响其他站。
 表格下方还有两个按钮：
    · 添加网站：贴入一个漫画详情页网址，程序自动探测这个站能不能下载，
 能下才让你加（详见下面「三、支持的站点 → 自己添加网站」）。
    · 删除站点：删掉自己添加的站点。内置站点删不掉（只能取消左边的勾来停用），
 选中内置站点点它会有一句提示。

改完点「保存」生效；点「恢复默认」还原所有配置。

自己添加网站（不用写规则文件）
------------------------------

这是给「我常看的站不在内置列表里」准备的。不需要会写代码，也不需要手改 JSON：

  1. 在浏览器里打开那个站的某本漫画的详情页（就是能看到章节列表的那一页），
 把地址栏的网址复制下来。注意要贴详情页，不是网站首页 —— 首页上找不到章节。
  2. 打开漫卷 → 设置 → 站点管理 → 点「添加网站」。
  3. 把网址粘进去，点「开始探测」。程序会自己：打开这个页面 → 找出章节链接 →
 抓一话看看能不能拿到正文图片 → 真下几张图试试 → 顺带找找这个站的搜索入口。
 通常几秒，慢的站要几十秒。
  4. 看结果：
     · 显示「探测通过：这个站可以下载 ✅」，下面的「添加到站点列表」按钮会亮起来。
 点它，这个站就加进来了，名字前面带 [自建]。
     · 显示「探测未通过 ❌」，按钮是灰的，加不了。下方会写清楚为什么。

为什么会有站探测不过？ 因为不是所有站都能靠「读懂网页」来下载：

  探测不过的原因          说明                                                                能不能救
  ----------------------------------------------------------------------------------------------------------------------
  图片靠 JavaScript 现拼  网页源码里根本没有图片地址，是浏览器打开后临时算出来的（            需要写专门适配器，暂时不行
                          常带服务端签名）。典型：动漫屋 dm5。
  拿不到正文图片          页面能打开，但图片要么要登录、要么被付费墙挡住                      换个不需要登录的站试试
  找不到章节链接          贴的是首页/列表页，或者是完全靠 JS 填章节的站                       确认贴的是详情页
  页面打不开              域名解析失败、站点关停、或者你本地网络到不了                        先在浏览器里确认能打开
  生成的规则跑不通        少数站结构太特殊，自动生成的规则在引擎里解析不出东西                需要手写规则文件

程序宁可拒绝添加，也不会给你加一个下下来全是广告图的死站。这是刻意的：
内置的每条规则都经过实测，自建的也应该有这个起码的保证。

想删掉自己加的站：在站点管理表格里选中它，点「删除站点」，确认一下就行。

三、支持的站点
==============

当前内置 22 条规则，其中 19 个是真实可用站点（已通过实网下载测试），
另外 2 条是给用户加新站用的模板，1 条 manhuagui 是 manhuagui_cc 的旧域名别名。

    | 内置列表之外的站：不用改代码，也不用写规则文件 ——
    | 设置 → 站点管理 → 「添加网站」，贴个详情页网址，程序自己探测能不能下，
    | 能下就加进来（名字带 [自建]）。详见上一节「自己添加网站」。
    | 自建的站和你手写的 rules/*.json 等效，存在配置文件里，升级程序不会丢。

    | 为什么有些站不在搜索下拉里：下拉只列能站内搜索的站点（当前 12 个）。
    | 其余站点已默认隐藏，但规则仍在、能通过「打开网址…」直接下载，
    | 也会在验证脚本里照跑。想让某个站重新出现在下拉里，把规则文件里的
    | "hidden": true 删掉即可。

六、自行添加新站点
==================

漫画站改版很频繁，软件把「怎么解析一个站」完全交给 JSON 规则，
你可以自己加新站，不用改代码。

步骤
----

    | 先试设置 → 站点管理 → 「添加网站」：多数站能自动搞定，不用往下看。
    | 只有在自动探测被拒（图靠 JS 现拼、要登录等）时，才需要手写规则。

  1. 找到漫画详情页 URL，看它的域名是不是新的。
  2. 复制模板：复制 mangakit/rules/templatedm.json 为 mangakit/rules/你的站点id.json。
  3. 用浏览器开发者工具（F12）看三处：详情页、章节列表、章节页的图片，
 把对应的 CSS 选择器填进规则。
  4. 命令行验证：python -m mangakit --url <你的详情页> --get 1 --limit 3。
  5. 确认能下载后，在设置里勾选启用。

手写的规则文件放在 mangakit/rules/ 下；如果想让规则跟着配置文件走（不依赖程序目录），
可以改用「添加网站」加进去 —— 两种方式在引擎眼里是等价的。

规则字段速查
------------

  ┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄
    {
      "id": "站点唯一id",
      "name": "显示名称",
      "lang": "cn",
      "note": "写清楚这个站的页面结构，改版时方便排查",
      "domains": ["example.com", "www.example.com"],   // 用来匹配网址
      "headers": { "Referer": "https://example.com/" }, // 每个站需要的请求头
      "cookies": "a=1; b=2",                            // 需要登录的站填这里

      "comic": {
        "title":  { "css": "h1", "text": true },
        "author": { "css": ".info a", "text": true },
        "cover":  { "css": ".cover img", "attr": "src" },
        "status": { "css": ".status", "text": true },
        "description": { "css": ".intro", "text": true },
        "tags":  { "css": ".tags a", "text": true, "all": true }
      },

      "chapters": {
        "list": { "css": "#chapterlist a" },      // 章节链接的选择器
        "url_re": "/chapter/\\d+",               // 过滤掉非章节链接（正则）
        "url_replace": [["/(\\d+)/(\\d+)/", "/$1/$2/all.html"]], // 改写章节链接
        "max_pages": 20,                          // 章节列表分页时最多翻几页
        "next": { "css": "a.next", "attr": "href" },// 翻页链接
        // 详情页只渲染最近 N 话时，用这两条之一补齐（点「展开全部章节」才触发）
        "api": {                                  // 通道 1：站方章节列表接口
          "url": "https://example.com/comic/{id}",
          "method": "POST", "data": {},
          "list": "data.chapters",                // 结果路径，$.* 表示根数组
          "title": "chapterName",
          "chapter_url": "/chapter/{contentId}-{id}.html"
        },
        "embed": {                                // 通道 2：完整数组内嵌在页面脚本里
          "start": "\\\"chapters\\\":(\\[)",       // 第 1 组 = 数组起点
          "item": "\"id\":\"([^\"]+)\",\"title\":\"([^\"]*)\"",  // 逐条，作用在反转义后的文本上
          "fields": ["id", "title"],
          "url": "/read/{comic_id}/{id}"
        }
      },

      "pages": {
        "list": { "css": ".reader img" },         // 图片元素选择器
        "url": { "attr": "src" },                 // 图片地址在哪个属性
        "filter": "\\.(?:jpg|png|webp)",         // 白名单正则，滤掉封面/广告图
        "replace": "/dup//dup/",                  // 修正图片 URL 里重复的路径段
        "lazy_js": "var\\s+imgs\\s*=\\s*\\[([^\\]]+)\\]", // 图片在 JS 变量里时用
        "split": "|||"                            // lazy_js 结果的分隔符
      },

      "search": {
        "url": "https://example.com/search?q={q}",
        "list": { "css": ".result li" },
        "link":  { "css": "a.thumb", "attr": "href" },
        "title": { "css": ".name", "text": true },
        "cover": { "css": "img", "attr": "data-original" }
      }
    }
  ┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄

字段选项
--------

  写法                        含义
  ----------------------------------------------------------------------------------------------------------------------
  "css": "..."                CSS 选择器；装了 cssselect 后支持 a[href*='/chapter/'] 这类写法
  "attr": "..."               取 HTML 属性（src / data-original / href / content / 任意自定义属性）
  "text": true                取元素文本
  "text": "direct"            只取元素自己的文字，不含内部子元素。标题里塞了分类标签时必须用它，否则标题会变成「作品名
                              都市 恋爱」
  "all": true                 取所有匹配元素的文本，而不是第一个
  "attr": ["content", "src"]  依次试多个属性，取第一个非空的（桌面/手机两套模板并存时用）
  "re": "作者：(.+)"          对取到的文本再套一层正则，用第 1 个捕获组
  "url": false                关掉自动补全网址。默认值会把取到的值当相对地址拼到当前页上；取 title / aria-label
                              这类纯文本属性时必须写它，否则「海贼王」会变成 https://站点/海贼王

常见情况怎么处理
----------------

  页面情况                                           做法
  ----------------------------------------------------------------------------------------------------------------------
  图片在 data-src / data-original 等懒加载属性       "url": {"attr": "data-original"}
  图片列表在 JS 变量里                               用 lazy_js 正则抓，多个值用 split 指定的分隔符隔开
  图片列表在 JSON 里                                 lazy_js 抓整个 JSON 数组（正则带括号），程序会自动解析
  页面只给「图片前缀 + 总张数」，不列 URL            把 lazy_js 写成字典（见下）
  标题元素里套着分类标签                             标题选择器加 "text": "direct"
  图片 URL 里有重复路径段 / 要换域名                 用 pages.replace 做正则替换
  章节页混着封面和广告图                             用 pages.filter 白名单正则过滤
  章节链接里混着别的链接                             用 chapters.url_re 过滤
  章节链接要改成另一种形式（如多页版 → 单页滚动版）  用 chapters.url_replace 正则改写，改写后撞车的会被去重
  详情页只渲染最近 20 话，其余在「加载更多」后面     加 chapters.api（有接口）或 chapters.embed（数据内嵌在页面里），
                                                     见下
  取的是 title/aria-label 这种文本属性               规格里加 "url": false，否则会被拼成假网址
  站需要登录                                         在规则里填 cookies，或用 --selftest 之外的方式手动带
  站搜索接口 500 / 是 JS 异步渲染                    删掉 search 段（GUI 会提示「不支持搜索」，改用「打开网址…」）
  页面是 gb2312/GBK 编码                             程序已自动处理，不用管

    | 注意：verify.py 现在会对声明了搜索关键词的用例断言搜索结果非空，
    | 所以规则写完后搜索坏掉不会再「全绿蒙混过关」。

lazy_js 写成字典：按张数展开图片
--------------------------------

有些站不逐张列出图片 URL，只在 JS 里给一个前缀和一个总张数：

  ┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄
    "pages": {
      "lazy_js": {
        "prefix": "var\\s+pasd\\s*=\\s*[\"']([^\"']+)[\"']",     // 第 1 个捕获组 = 图片前缀
        "count":  "var\\s+num\\s*=\\s*eval\\(\\s*[\"']?(\\d+)", // 第 1 个捕获组 = 总张数
        "start":  1,        // 从第几张开始（可写在 lazy_js 里或 pages 层）
        "suffix": ".webp",  // 每张的后缀（同上）
        "width":  3         // 序号补零宽度，如 001（同上）
      },
      "filter": "\\.webp$"
    }
  ┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄

展开结果就是 前缀 + 1 + .webp、前缀 + 2 + .webp …… 直到张数用完。

replace：修正图片 URL
---------------------

  ┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄
    "replace": "/kblmh//kblmh/"        // 单个正则 → 删掉匹配到的部分
    "replace": [["/old/", "/new/"]]    // 或 [[正则, 替换], ...] 逐条替换
  ┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄

在 filter 之后、去重之前执行 —— 专门对付图床下发畸形 URL 的情况
（如重复路径段，双层路径 404、去掉一层就 200）。

chapters.api / chapters.embed：补齐折叠章节
-------------------------------------------

很多站的详情页只画最近 20 话，剩下的在「加载更多章节」按钮后面，HTML 里根本没有。
配了这两条之一后，GUI 的「展开全部章节」按钮就能把它们补回来。

通道 1 chapters.api —— 站方有章节列表接口：

  ┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄
    "api": {
      "url": "https://www.dingmanhua.com/comic/{id}",
      "method": "POST",
      "data": {},
      "list": "data.chapters",
      "title": "chapterName",
      "chapter_url": "/chapter/{contentId}-{id}.html",
      "headers": { "X-Requested-With": "XMLHttpRequest" }
    }
  ┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄

  · {id} 是详情页 URL 的最后一段（comic/278.html → 278，会自动去掉 .html 后缀）。
  · list 是结果里的路径，$.* 表示根数组。
  · 章节地址的模板键不能叫 url（那个键已经被接口地址占用了），用 chapter_url；
 模板里可用接口返回的全部字段加 {id}/{cid}/{slug}（去后缀的 id）。
  · 接口报错只会记一条 warning 日志并返回空列表，不会让展开失败。

通道 2 chapters.embed —— 完整数组就内嵌在页面脚本里：

  ┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄
    "embed": {
      "start": "\\\"chapters\\\":(\\[)",
      "item": "\"id\":\"([^\"]+)\",\"title\":\"([^\"]*)\"",
      "fields": ["id", "title"],
      "url": "/read/{comic_id}/{id}"
    }
  ┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄

  · start 在原始 HTML 上匹配，第 1 个捕获组是数组起点；程序从那里做括号配平
 截出完整 JSON 片段，再 json.loads 还原转义（别用 unicode_escape 手工解码，中文会乱）。
  · item 作用在已反转义的文本上，所以只需要匹配普通原文，不用写双层反斜杠。
  · url 模板可用 fields 里的占位符，外加 {comic_id} / {cid}（作品 id）。
  · HTML 里同一个键可能出现多次（如 Next.js 的 "chapters" 有时是 $22:props:... 这种引用），
 start 写得不够精确就可能匹到引用而不是数组 —— 写完务必跑一次 verify.py 看章节数对不对。

    | 两条通道都只在用户点「展开全部章节」时才走，正常打开漫画不受影响，
    | 也不会拖慢首屏。

七、故障排查
============

通用步骤
--------

  1. 先看日志：%APPDATA%\mangakit\logs\mangakit.log 里能找到具体错误。
  2. 命令行复现：python -m mangakit --url <网址> 看解析到哪一步失败。
  3. 离线自检：python -m mangakit --selftest r.txt 检查配置、规则、数据库、打包器是否正常。
  4. 禁用问题站点：设置 → 站点管理里取消勾选。

下载报「拒绝访问 / Permission denied」
--------------------------------------

这是最常见的一类报错，而且大多数情况不是程序坏了，是程序被放在了一个写不进去的地方。

新版在下载前会做一次真实落盘自检（建目录 + 试建文件），失败时直接报：

  ┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄
    无法写入目录：C:\Users\你的用户名\Downloads\MangaKit\某本漫画
    原因：系统拒绝访问（权限不足，或该目录被其它程序占用）
    怎么办：
      1) 把 MangaKit.exe 移到桌面或「文档」目录再运行
      2) 或在「设置 → 下载目录」改一个能写的路径
      3) 关掉占用该目录的其它程序
  ┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄

按顺序排查：

  现象                                    判断                                    对策
  ----------------------------------------------------------------------------------------------------------------------
  exe 在开发工具 / 沙箱 /                 工作区外的路径被系统策略限制，          把 exe 和 bat
  隔离环境的工作区里                      建目录常常还能成功，但建文件一定失败    一起复制到桌面或「文档」，在那里运行
  程序旁边出现了 MangaKitData 文件夹      说明 %APPDATA% 不可写，                 同上，换个位置运行
                                          程序退回了便携模式——这是同一个病的症状
  exe 装在 C:\Program Files 下            普通用户对子目录没有写权限              用便携模式（数据写在 exe 旁边），或把
                                                                                  exe 移走
  下载目录被别的程序占用                  图片查看器/同步盘/杀软锁住了目录        关掉占用它的程序，或换一个空目录
  磁盘满了                                —                                       清理磁盘；
                                                                                  程序会报「磁盘空间不足」而不是「拒绝访

    | 如果桌面这份能下载，问题就出在原来那个位置，跟 MangaKit 无关。

验证 exe 本身是否正常
---------------------

打包后的 exe 没有控制台，用文件输出的自检通道：

  ┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄

  ┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄

四步全 OK 会以 SELFTEST PASS 结尾；结果也会写到同目录 selftest.txt。

重新获取已过期签名（kanman）
----------------------------

kanman 的图片地址带时间戳签名。正确做法：重新打开该章节的详情/阅读页，让程序重新解析一次，
再点下载。不要拿几小时前复制的旧章节列表反复重试。

八、数据与隐私
==============

  · 所有抓取、解析、下载都在本机完成，不经过任何第三方服务器。
  · 只向漫画站点发请求。程序不会上传任何数据。
  · 数据都在 %APPDATA%\mangakit\：配置、数据库、日志（该目录不可写时会自动改用 exe 旁的 MangaKitData\）。
  · 卸载：删掉 exe 和 %APPDATA%\mangakit\ 目录即可，没有注册表项、没有系统服务。
  · 想换数据目录，设环境变量 MANGAKIT_HOME。
  · 请遵守目标站点的版权规定与 robots 协议，仅供个人学习与备份使用。

------------

  ┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄

    python -m PyInstaller --noconfirm --clean mangakit.spec

    # 打包后 exe 的端到端冒烟（6 个站各下 2 张图）
    python tools\exe_smoke.py

    python tools\gui_smoke.py

    python tools\t_probe.py https://songzimanhua.com/book/15293/

    # 通用闭环：探测 → 写进 user_rules → 重载注册表 → 引擎真跑一遍 → 清理
    python tools\t_roundtrip2.py https://songzimanhua.com/book/15293/

    # 用站点自己的搜索接口找真实详情页，再批量探测（找正面用例用）
    python tools\t_probe_real.py

    # 走真 GUI 对话框 + 真探测：加进去、看列表、再删掉
    python tools\t_gui_addsite.py
  ┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄

tools\verify.py 会真的去每个站点抓详情页、章节列表、章节页，并下载每站 3 张图；
cases.json 里带 search 字段的用例还会断言站内搜索结果非空。
结果写到 tools\verify.out.json，同时在 <下载目录>\_verify\<站点id>\ 下留下样本图
（每次跑之前会清空，所以看到的一定是这次的）。
站点改版后跑一遍就知道哪些坏了。

tools\exe_smoke.py 专测打包产物：它会为每个站点单独准备 MANGAKIT_HOME，
跑 MangaKit.exe --url … --get 1 --limit 2，然后检查磁盘上真的落盘了图片，
最后报 exe 冒烟 N/6 站有真实图片落盘。改完代码只跑源码测试是不够的 ——
打包环境独有的问题（相对导入、stdout 编码、资源目录、onefile 解包）只有它能抓到。

    | 重打包前先关掉正在运行的 exe：
    | Get-Process -Name MangaKit | Stop-Process -Force
    | 否则 PyInstaller 写 dist\MangaKit.exe 会报 PermissionError: [WinError 5] 拒绝访问。
    | 打包产物残留：onefile 会把自身解包到 tools\_smoke\_MEIxxxxxx\（几百 MB dll），
    | 跑完可以直接删；exe 还在跑时删不掉，先 Stop-Process。

    | - 勾选框曾因为「缩进 30px > 勾选列宽 28px」被画到章节标题上，
    |  表现为「勾不上 + 点下载无反应」；
    | - 勾选框位置修好后，点「下载选中章节」跳任务页的左侧导航高亮没跟着走，
    |  下次点导航会把内容切回搜索页，看着像程序自己跳回去了；
    | - 展开折叠章节时展开前的勾选会被清空（复原逻辑原本挂在信号回调里，
    |  任何一次重绘都会丢），现在复原统一在渲染层做，并按 (url, cid) 匹配；
    | - 全站搜索原本 gather 等全部站才显示，最慢的站拖住整屏，表现为长时间空列表；
    |  现在每站单独走 search_partial 推过来（实测首批 0.38s、全量 3.08s）；
    | - 封面原本在 GUI 线程里同步 httpx.get（每张 8s 超时），
    |  bzmanga 一次 83 条结果 = 最多上百秒界面冻结；现在占位图毫秒级返回，
    |  封面由 CoverLoader 线程池（6 线程）后台取，取到一张刷一张；
    | - 收藏页「删除选中」原本点了就删、没有确认，误点一下收藏就没了，
    |  而且只支持单选、没有右键菜单、计数不刷新；现在删除/清空都带确认，
    |  支持多选与右键菜单，底部实时显示条数，空库时按钮自动置灰。
    | - 「展开全部章节」原本只看章节列表非空就点亮。实测 22 个站里只有 3 个
    |  配了补齐通道，用户在其余站点点下去只会白等一次完整重载、列表纹丝不动，
    |  且没有任何提示，看着就像功能坏了。现在按钮可用性由 Site.can_expand
    |  决定：支持的站点亮起并说明「点此展开折叠隐藏的其余章节」，不支持的置灰并
    |  说明「已给出全部章节，无需展开」；展开完成后再给一句
    |  「展开完成：新增 N 话，共 M 话」的回执。
    | - 全站搜索的收尾信号 search_done(int) 原本会掉进 _add_items(results) 分支，
    |  抛 TypeError: 'int' object is not iterable 把搜索打断；现在先判 int
    |  再走列表分支。
    | - 「添加网站」这条防的是假成功：探测阶段用的是宽松识别逻辑，规则阶段要交给
    |  引擎的 Selector+url_re 去认，两者不等价。早期版本出现过「探测报 62 话、
    |  实测图片可下载」，写成规则后引擎解析出 0 章（标题还识别成导航栏的「登录」）。
    |  现在 _verify_rule() 会把生成的规则真跑一遍 parse_chapters/parse_pages，
    |  不过就拒绝添加 —— 宁可拒，也不写一条看着能用的死规则。
    | test_write_guard.py 防的是另一类回归：曾经因为下载器先抓页、后检查目录能不能写，
    | 用户要等抓完十几张图才看到一句 PermissionError: [WinError 5] 拒绝访问。
    | 现在可写性闸门排在联网之前，这条断言会直接调 _download_chapter() 检查它抛的是
    | WriteDenied（带修复建议）而不是裸 PermissionError。
    | test_block.py 里「站方故障」那几条防的回归是：站点数据库挂掉时会用
    | HTTP 200 + 51 字节人话（如 数据库链接失败：SQLSTATE[HY000] [1040] Too many connections）
    | 代替整个页面。早期版本把它当正常 HTML 往下解析，最后报「没有章节」——
    | 看着像规则失效，实际是站方问题。同理也要确保正常漫画页里出现的
    | 「数据库」「SQLState」等字样不会被误判成故障。
